  ● Merci pour ce retour détaillé — plusieurs vrais bugs are là. Je les prends un par un :

  1. L'erreur "VM is locked (suspending)" qui marche quand même — Proxmox renvoie parfois une erreur de tâche
  alors que le suspend --todisk a réellement fini. Notre code faisait confiance au statut de la tâche au lieu
  de vérifier la réalité.

  2. Doublon de clone au refresh pendant un Start — le vrai bug : la ligne VM n'est créée en base qu'après le
  clone+start (qui peut prendre du temps sur un vrai Proxmox). Si tu rafraîchis pendant ce laps de temps, rien
  n'est encore visible en base → la page affiche "Start" à nouveau → un second clic clone une deuxième VM.

  3. Le front ne reflète pas l'hibernation — le heartbeat ne fait qu'un aller simple (front → back), il ne
  rapatrie jamais l'état réel. Donc si le statut change côté serveur (auto-pause), rien ne le signale au front
  tant que tu ne rafraîchis pas la page.

  4. Le minuteur — une fois le point 3 corrigé, il s'arrête tout seul (le composant masque déjà le countdown
  quand paused est vrai).

  5. Reprise après hibernation — oui, une vraie reprise à l'identique : c'est un hibernate disque complet
  (RAM+CPU sauvegardés), d, sessions ouvertes dans la VM sont restaurésonc les processus, connexions exactement
  comme avant la pause — pas un redémarrage à froid.
